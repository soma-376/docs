# 0030. 웹 세션과 갱신 상태를 공유 Valkey에 저장한다

## Status

Accepted — 사용자 승인. 기존 frontend의 토큰 포함 쿠키·단일 프로세스 갱신 조율을 대체한다. BFF 중계·CSRF·백엔드 인증/인가·CLI 계약은 유지한다.

## Context

frontend BFF 여러 인스턴스의 메모리 Map은 같은 refresh token의 동시 제출을 막지 못한다. backend는 소비한 refresh token 재사용 시 세션을 폐기한다. infra의 공유 Valkey를 사용해 frontend가 웹 세션을 조율한다.

## Decision

- 브라우저에는 인증 암호화된 v2 세션 식별자·만료 시각만 저장한다. AT/RT는 환경별 Valkey 키에 암호화 저장한다. Valkey만 사용하고 기존 토큰 쿠키·메모리 갱신 모드는 제거한다. v1 쿠키는 재로그인을 요구하며 자동 이관하지 않는다.
- 키는 `<dev|prod>:bff:session:<id>`이며 한 세션의 암호화 payload·revision·갱신 소유자·시작 시각을 같은 JSON 값에 둔다. 로그인마다 새로운 난수 ID를 만든다.
- Lua로 idle 상태와 revision을 확인한 뒤 갱신 담당자를 지정한다. 담당자만 backend refresh를 호출하고, 다른 요청은 제한 시간 안에서 GET으로 결과를 기다린다.
- 완료 저장은 세션 존재·revision·소유자를 함께 확인한다. 로그아웃은 공유 세션을 먼저 제거해 지연 갱신의 세션 부활을 막는다. 늦은 실패 응답으로 브라우저의 새 로그인 쿠키를 삭제하지 않는다.
- 세션 TTL은 최초 로그인 기준 30일 절대 만료다. 갱신·조회로 연장하지 않는다. refresh 상태의 키는 lease 만료로 자동 재획득하지 않는다.
- refresh 결과가 불명확하거나 담당자가 중단된 세션은 재로그인한다. 오래된 RT를 재제출하지 않는다. 진행 중인 정상 갱신은 대기하며 대기 한도 초과는 일시 오류다.
- Valkey 연결 장애는 503이며 세션 쿠키를 지우거나 메모리 갱신으로 우회하지 않는다. 세션 부재·만료·복구 불가 상태는 401이다. 로그인 페이지는 확인 오류가 있어도 폼과 재시도를 제공한다.
- TLS 및 환경별 IAM 사용자/키 ACL을 사용한다. IAM 연결 인증은 주기적으로 재인증한다. 서버 전용 암호화 키는 기존 Secrets Manager 경로로 제공한다.

## Alternatives Considered

- backend에서 RT 중복 갱신 허용: 엄격한 재사용 탐지 정책을 유지하기 위해 채택하지 않는다.
- BFF 직접 DB 접근: 별도 연결 풀·네트워크·스키마 관리 대신 준비된 Valkey를 사용한다.

## Consequences/Tradeoffs

### Positive

- 정상적인 다중 BFF 동시 요청은 하나의 갱신 결과를 공유한다. 토큰 갱신마다 쿠키를 쓰지 않는다.

### Negative

- Valkey 장애 동안 인증 요청도 실패한다. 메모리 축출·유실 시 재로그인이 필요하다.
- Valkey와 backend는 원자적 트랜잭션이 아니다. 장애 조치로 승인된 쓰기가 유실되면 중복 갱신을 완전히 보장할 수 없다. backend 재사용 탐지를 유지한다.
- v1에서 v2로 전환할 때 기존 로그인은 다시 해야 한다. 이전 버전 태스크와 새 버전을 혼합 처리하지 않는다.

## Acceptance Criteria

- 두 BFF에서 같은 세션을 갱신해도 backend 호출이 한 번이다.
- 로그아웃 경쟁·갱신 응답 유실·Valkey 장애·절대 TTL·암호화 저장·환경 격리를 검증한다.
