# 0017. 데스크톱 설치와 제거를 사용자별 설치 기록으로 연결한다

## Status

Accepted

## Context

telemetryctl의 GUI 패키지와 pulsemetry-backend의 curl/irm 부트스트랩은 별도 실행 파일을 설치한다.
GUI 파일만 삭제하면 데몬의 자동 시작과 벤더 설정이 남는다. 기존 telemetryctl ADR 0022는
설정과 자격증명 제거를 구현하지만 실행 파일 삭제와 OS 제거 진입점은 패키징의 책임으로 남긴다.
두 레포가 설치 기록과 제거 도구를 공유해야 터미널 없이 제거할 수 있다.

## Decision

- GUI와 데몬은 현재 OS 사용자 범위로 설치한다. Windows GUI 설치도 사용자별 범위로 맞춘다.
- telemetryctl은 설치 기록, 제거 엔진, 사용자 확인 화면, OS 제거 진입점을 소유한다.
  backend 부트스트랩은 설치한 실행 파일을 이 엔진에 등록한다. 서버 enrollment 응답은 바꾸지 않는다.
- 설치 기록은 프로그램 파일의 절대 경로와 적용 지문을 저장한다. 설정/토큰 원문은 저장하지 않는다.
  GUI 패키지와 CLI 설치의 기록은 함께 읽되 각 구성요소의 소유권을 구분한다.
- 제거 도구는 GUI·데몬과 별도 프로세스로 실행한다. GUI가 삭제되거나 데몬이 꺼져 있어도
  설치된 제거 진입점에서 다시 실행할 수 있어야 한다.
- 제거 화면은 프로그램·연결 설정 제거와 로컬 사용 기록 삭제를 구분한다. 로컬 DB는 기본 보존한다.
  서버에 전송된 기록과 서버 토큰 폐기는 로컬 제거에 포함되지 않는다.
- 자동 시작 해제, 데몬 정상 종료, 관리 설정 해제, 로컬 자격증명 정리, 프로그램 파일 삭제 순서를 지킨다.
  앞 단계가 실패하면 후속 삭제를 하지 않고 오류와 재시도 경로를 표시한다.
- 사용자 설정 보존과 데몬 종료 인증은 telemetryctl ADR 0022를 유지한다.
  삭제는 등록한 파일만 대상으로 한다. 개발 체크아웃, 바뀐 파일, 사용자 추가 파일을 재귀 삭제하지 않는다.
- 제거 도구와 설치 기록은 재시도에 필요한 동안 보존한다. 최종 정리는 실행 중 파일을 삭제할 수 있는
  OS별 방식으로 수행하며, 정리가 끝나기 전 완료로 표시하지 않는다.

## Alternatives Considered

### A. GUI 패키지만 제거한다
- 장점: OS 패키저의 기본 제거 기능을 그대로 쓴다.
- 단점: 자동 시작과 벤더 설정이 남는다.
- 탈락 이유: 사용자가 제거한 제품이 계속 수집하는 상태가 된다.

### B. GUI가 모든 제거를 직접 실행한다
- 장점: 별도 프로세스가 필요 없다.
- 단점: GUI가 없거나 고장 난 경우 제거할 수 없고 자신의 실행 파일 삭제와 충돌한다.
- 탈락 이유: 실패 후 재시도 경로가 제품 실행 상태에 의존한다.

## Consequences/Tradeoffs

### Positive
- 패키지 설치와 부트스트랩 설치를 같은 사용자 경험으로 제거한다.
- 기록과 지문을 통해 사용자 변경을 보존하고 중단된 제거를 재시도한다.

### Negative
- OS별 제거 진입점과 프로그램 파일 기록을 유지해야 한다.
- 기존 시스템 전체 Windows 설치는 사용자별 설치로 자동 인수하지 않는다.
- 변경된 관리 파일은 남을 수 있으므로 제거 결과에 보존 사유를 표시해야 한다.

## Acceptance Criteria

- Windows 앱 제거, macOS 제거 도구, Linux 제거 진입점에서 터미널 입력 없이 제거한다.
- 부트스트랩으로 CLI·GUI를 설치한 경우와 GUI 패키지만 설치한 경우에 제거 화면이 동작한다.
- 실행 중 데몬, 이미 꺼진 데몬, GUI 파일 선삭제, 실패 후 재시도를 검증한다.
- 사용자 파일 보존과 선택적 DB 삭제를 임시 설치 및 가짜 자격증명으로 검증한다.
