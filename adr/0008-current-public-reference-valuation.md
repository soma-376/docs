# 0008. 사용 환산액은 버전을 고정한 현재 공시 표준 단가로 평가한다.

## Status

Accepted — 부분 대체: [ADR 0009](0009-current-reference-cache-benchmark-and-revaluation.md)가 v3의 캐시 생성 5분 평가 기준, 검증된 Codex 의미와 승인된 과거 재평가를 구체화한다. v1/v2의 불변 정책, 과거 실제 청구액·조직 계약액과의 구분은 유효하다.

## Context

PRD 제품 원칙 3과 Dashboard 계약은 공시 금액과 계약 금액을 나눈다. backend ADR 0020의 추정 비용은
검증된 불변 가격 프로파일만 허용하지만 가격표의 소유·저장·갱신이 미결이었다. 기존 가격 단계는 사건 시각의
유효 요금만 선택한다. 현재 공시 단가를 과거 사용량의 환산 기준으로 쓰려면 두 기준을 구분해야 한다.

이 결정은 backend의 적재·조회와 frontend의 사용 환산액 해석에 걸린다. 사용자가 지정한 현재 GPT·Claude의
공식 공시 단가를 기준으로 삼으며, 실제 계정의 할인·서비스 등급·리전·청구서를 추정하는 작업은 아니다.

## Decision

1. 가격 프로파일은 `event_time`과 `current_reference`를 구분한다. 전자는 원천 사건 시각, 후자는 프로파일의
   고정된 `referenceAsOf` 시각으로 가격 유효성을 선택한다. 원천 시각은 바꾸지 않고 임의의 과거 유효 시작일을 만들지 않는다.
2. 현재 기준 환산은 직접 공급자의 **Standard·global·USD·토큰 사용량**을 평가 기준으로 명시한다. 이는 누락된
   실제 서비스 등급을 Standard라고 판정한 것이 아니다. 실제 청구액·구독 금액·세금·환율·도구 사용료와 분리한다.
3. backend가 가격표와 근거를 버전 관리한다. 프로파일에는 불변 ID, 조회 기준 시각, 통화, 평가 기준,
   공급자 공식 URL과 정확한 모델 ID·성분별 단가를 둔다. 외부 조회 없이 결정적으로 계산하고 `pricing_version`으로 연결한다.
4. **v1/v2 정책 — v3는 ADR 0009로 대체됨.** 검증된 producer 의미와 정확한 모델·모든 필요한 토큰 성분이 있어야 한다. 모르는 모델·의미·조건은 null이다.
   Claude cache creation이 명시적으로 0이면 TTL에 따른 금액도 0이므로 TTL 구분이 필요 없다.
   양수인데 5분/1시간 성분을 알 수 없으면 금액을 계산하지 않는다. 미보고 null을 0으로 보지 않는다.
5. **초기 지원 범위 — ADR 0009가 검증된 Codex 범위를 확장한다.** 검증된 Claude exclusive 프로파일과 공식 네 모델을 먼저 연결한다. Codex의 원천 의미가 확인되지 않은
   범위는 공식 모델 가격이 있어도 null을 유지한다. 검증되지 않은 의미나 TTL을 fixture 식별자로 우회하지 않는다.
6. 가격표 개정은 새 `pricing_version`과 정규화 판을 만든다. 저장된 기존 분석행을 자동 갱신하지 않는다.
   과거 재평가는 별도 승인된 재처리와 범위·영향 대조가 필요하다. 서로 다른 가격 판을 같은 과거 청구 기준이라고 주장하지 않는다.

## Alternatives Considered

### 사건 시각에 현재 요금표를 소급해 유효하다고 선언한다

구현은 작지만 과거 가격의 증거를 꾸미게 된다. 명시적인 현재 기준 평가와 구분할 수 없어 채택하지 않는다.

### 벤더 보고 비용으로 빈 추정액을 채운다

서로 다른 성격의 금액을 합치므로 채택하지 않는다. 보고 비용과 추정 비용은 계속 별개다.

### 모든 미보고 차원을 기본값으로 채운다

표시는 넓어지지만 토큰 포함관계나 cache TTL의 근거가 사라진다. 표준 평가 기준과 원천 성분의 결손은 다른 문제다.

## Consequences/Tradeoffs

### Positive

- 현재 공식 표준 요금을 같은 기준으로 적용하며 불변 버전으로 계산을 재현한다.
- 원천 시각·원본·실제 보고 비용을 보존하고 알 수 없는 성분은 null로 남긴다.

### Negative

- 과거 사용량의 평가 금액은 과거 청구액이 아니다. 화면과 내보내기 해석에 이 구분을 유지해야 한다.
- cache TTL이나 producer 의미가 부족한 사용량은 여전히 비용 집계를 완성하지 못한다.
- 요금표 갱신과 과거 재평가는 명시적인 버전·검증 작업이 필요하며 자동 최신 조회는 하지 않는다.

## Acceptance Criteria

- 같은 입력·프로파일은 같은 Decimal 금액과 분석 hash를 만든다.
- 사건 시각 기준의 기존 반개방 유효기간 검증은 유지하고 현재 기준은 고정된 조회 시각으로 별도 검증한다.
- 미지 모델·미검증 의미·cache 미보고/양수 TTL 불명은 null이며 보고 비용과 원천 시각은 바뀌지 않는다.
- 정상 수집 진입점으로 제출한 독립 파생 데이터의 금액을 입력 정수와 Decimal 단가에서 계산해 적재·API·Chrome과 대조한다.
