# 0009. 사용 환산액은 캐시 생성 5분 기준과 검증된 토큰 의미로 과거 관측도 재평가한다.

## Status

Accepted — ADR 0008의 캐시 생성 TTL 미확인 시 일괄 null 결정과 기존 검증 행의 재평가 범위를 구체화한다. 현재 참조 평가와 실제 청구액의 분리, 원천 보존, 불변 가격 버전, 미검증 의미를 계산하지 않는 원칙은 유효하다.

기본 가격판은 [ADR 0010](0010-current-reference-luna-model-pricing.md)에서 v4로 개정한다. 이 문서의 v3 정의와 기존 평가 결과는 보존한다.

## Context

사용 환산액은 실제 청구액이 아니라 같은 공시 기준에서 사용량을 비교하는 지표다. ADR 0008은 Standard/global 평가 기준을 고정했지만 Claude 캐시 생성의 TTL이 원천에 없으면 금액을 계산하지 않았다. 이 정책에서는 캐시 생성량 자체가 알려져 있어도 환산액을 표시할 수 없다.

기존 검증은 가격을 연결하기 전의 분석 행을 보존하고 새 파생 관측으로 가격 경로를 검증했다. 사용자는 캐시 생성에 5분 공시 단가를 평가 기준으로 적용하고, Codex 토큰 포함관계를 근거로 확인한 뒤 계산하며, 기존 데이터도 재평가하도록 승인했다. 이 결정은 backend의 가격·재처리와 frontend의 환산액 해석에 걸린다.

## Decision

1. 현재 참조 평가의 기준을 Standard/global/USD와 Claude 캐시 생성 **5분 공시 단가**로 고정한다. 실제 TTL이 5분이었다는 관측 사실을 만들지 않는다. 원천의 캐시 생성량이 알려져 있으면 이 기준으로 평가하며, 미보고 성분은 0으로 채우지 않는다.
2. Codex는 정확한 producer 버전과 이벤트의 input·cached input·output·reasoning 포함관계를 원천 구현과 검증 fixture로 확인한 범위만 계산한다. `codex-responses-inclusive-v1`은 input에 cache read/write가 포함되고 output에 reasoning이 포함된 의미다. cache read/write를 빼서 uncached input을 얻으며, 총량의 별도 보고인 tool token을 더하지 않는다. 확인되지 않은 버전·필드 의미·모델·필수 성분은 null을 유지한다.
3. 기존 가격 v1/v2의 ID·단가·기준 시각·평가 정책은 변경하지 않는다. 새 평가 정책은 새 불변 v3 프로파일과 정규화 판으로 구분한다. `pricing_version`에서 출처·기준 시각·평가 조건을 추적한다.
4. 승인된 기존 데이터는 새 프로파일로 재처리한다. 이번 범위는 main 검증 조직의 기존 primary 사용량 전체이며 v1 가격 관측도 포함한다. 다른 baseline 조직은 당시 증거로 유지한다. 원천 시각·원본 아카이브·관측 식별자는 보존하고 같은 관측의 최신 분석 판만 교체한다. 과거 검증 결과는 당시 판의 증거로 보존하며 새 결과와 구분한다.
5. 재처리는 내부 운영 경로에서 범위와 입력을 고정해 수행한다. 전후 관측 ID 집합·원천 성분·귀속·수신 이력과 금액 변화의 범위를 대조한다. 계산 가능한 행, 여전히 null인 행과 그 사유를 각각 기록한다. 대시보드 조회는 분석 원천을 수정하지 않는다.
6. 재평가 후 새로운 snapshot으로 개요의 일별 환산액과 팀별 누적 환산액을 검증한다. 일별 독립 기대값과 누적 합계를 대조하며, 실제 누락 행을 0으로 바꾸거나 누적선의 누락 구간을 이어 붙이지 않는다.
7. 서로 다른 producer의 의미 프로파일이라도 같은 비중복 canonical 성분(`input_uncached`·`output`·`cache_read`·`cache_create`)으로 검증된 호환 집합은 합산한다. 초기 호환 집합은 `claude-code-exclusive-v1`과 `codex-responses-inclusive-v1`이다. 알 수 없는 프로파일·누락 성분·미검증 행은 계속 해당 총합을 차단한다. 가격 판 혼재를 허용하는 변경은 아니며 기존 혼재 사유는 유지한다.
8. 공식 단가에 단일 요청의 길이별 요율이 있으면 그 요청의 검증된 입력 토큰 수로 구간을 고른다. `gpt-6-astra`는 input이 272,000을 초과할 때 입력·cache 단가를 2배, output 단가를 1.5배 적용한다. 단일 응답인 것이 확인되지 않은 여러 요청의 누계를 한 요청의 길이로 취급하지 않는다.

## Alternatives Considered

### TTL을 모르면 모든 캐시 생성 비용을 계속 null로 둔다

실제 청구액의 추정에는 보수적이지만 고정 기준의 사용 환산액이라는 제품 목적과 사용자가 선택한 평가 기준을 반영하지 못한다.

### 실제 TTL·미보고 토큰 성분을 5분·0으로 고쳐 저장한다

평가 조건과 관측 사실을 섞으므로 채택하지 않는다. 원천은 보존하고 평가 정책만 버전으로 구분한다.

### 조회 때 총 토큰에 최신 단가 하나를 곱한다

캐시·출력의 다른 단가를 잃고 같은 snapshot의 재현성을 깨므로 채택하지 않는다.

## Consequences/Tradeoffs

### Positive

- 캐시 생성량을 포함한 사용량을 동일한 공개 평가 기준으로 비교한다.
- 원본과 이전 가격표를 보존하면서 기존 관측의 계산 가능한 환산액을 복구한다.
- Codex의 토큰 포함관계를 검증해 이중 계산을 방지한다.

### Negative

- 5분 기준 환산액은 실제 TTL이나 실제 청구액과 다를 수 있다.
- 기존 snapshot·검증 기대값은 새 재평가 결과와 구분해야 한다.
- 원천 성분 또는 검증 근거가 부족한 관측은 여전히 null이다.

## Acceptance Criteria

- 이전 v1/v2 입력과 가격 프로파일의 회귀 결과가 변하지 않는다.
- v3의 캐시 생성 0·양수·누락을 각각 검증한다. 양수는 독립 Decimal 기대값과 일치하고 누락은 null이다.
- Codex 지원 범위의 포함관계와 가격 산식은 원천 근거와 독립 fixture로 확인한다.
- 재처리 전후 최신 관측 수와 ID 집합이 같고 원본 아카이브와 과거 검증 산출물이 보존된다.
- 10월 1–7일의 API·실제 화면에서 개요 일별값과 팀별 누적값을 동일 원천의 독립 기대값으로 대조한다.
