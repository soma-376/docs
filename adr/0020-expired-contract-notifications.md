# 0020. 만료 계약은 공통 알림함에서 갱신 폼으로 연결한다

## Status

Accepted — ADR 0018의 현재 계약 상태 조회와 ADR 0019의 화면별 응답 원칙을 확장한다. 계약 미입력 안내와 기존 규칙 알림의 확인 처리는 유지한다.

## Context

pulsemetry-backend와 pulsemetry-frontend는 계약 만료를 설정 목록에서 표시한다. 관리자는 다른 페이지에서도 만료 계약을 발견하고 해당 계약을 바로 갱신할 수 있어야 한다. 공통 헤더에 계약 안내를 계속 추가하면 수집 상태와 조회 도구를 보기 어려워진다.

## Decision

- 만료 계약은 모든 페이지의 공통 알림함에 벤더별로 표시한다. 벤더 이름, 계약 종료일, ‘계약 갱신’ 동작을 제공한다. 이 동작은 `/settings?vendor={vendorId}`의 해당 계약 편집 폼을 연다.
- `/contract-input-status`의 기존 `requiredCount/vendors`를 유지하고 `expiredCount/expiredContracts`를 추가한다. 만료 항목은 `vendorId/displayName/endDate`만 반환한다. 같은 등록 계약 조회에서 두 목록을 만들며 전체 설정·관측·좌석·청구를 조회하지 않는다.
- 보관되지 않은 등록 벤더의 최신 저장 계약만 판정한다. KST 종료일 당일까지 유효하고 다음 날부터 만료다. 계약 미입력·시작 예정·종료일 없는 계약은 만료로 세지 않는다. 종료일, 표시 이름, 벤더 ID 순으로 정렬한다.
- 알림 벨은 미확인 규칙 알림과 현재 만료 계약 수를 합산한다. 두 조회 중 하나라도 실패하거나 아직 완료되지 않으면 전체가 0건이라고 표시하지 않는다. 알림함에서는 각 조회 실패를 별도로 표시하고 재시도한다.
- 계약 만료는 현재 조치가 필요한 상태다. 별도 확인 기록이나 규칙 평가 이력을 만들지 않으며 계약을 갱신해 더 이상 만료가 아니면 알림에서 사라진다. 계약 저장 성공 시 조직 조회 캐시를 무효화해 목록과 건수를 함께 갱신한다.
- 기존 계약 미입력 안내는 헤더와 벤더 행에 유지한다. 만료 계약 안내를 설정 상단의 별도 섹션으로 중복하지 않는다. 운영·보안의 규칙 알림 목록과 CSV에 계약 알림을 섞지 않는다.

## Alternatives Considered

만료 계약을 규칙 알림으로 저장하면 갱신 상태와 확인 기록의 동기화가 필요하다. 현재 등록 계약으로 바로 판정할 수 있으므로 현재 상태 조회를 사용한다. 공통 헤더에 만료 배너를 추가하는 방식은 알림함과 안내가 중복되어 선택하지 않는다.

## Consequences/Tradeoffs

### Positive

모든 페이지에서 만료 계약을 발견하고 해당 폼으로 바로 이동한다. 추가 집계 없이 갱신 후 상태를 일치시킨다.

### Negative

이 알림에는 과거 만료 이력이나 사용자의 읽음 상태가 없다. 프론트와 백엔드가 추가 응답 필드를 함께 반영해야 한다.
