# 0018. 개요의 수집 미완료 사유와 조직 계약 입력 상태를 분리해 제공한다

## Status

Accepted — ADR 0017의 지표 사유 계약을 확장한다. backend ADR 0042의 완전성 판정 기준과 비교 조건은 유지한다.

## Context

pulsemetry-backend와 pulsemetry-frontend에서 개요의 ‘일부 관측’이 집계 대기인지 수집 공백인지 구분되지 않는다. 등록 벤더의 계약 미입력도 공통 화면에서 발견하기 어렵다. 계약은 필수 필드를 모두 검증한 뒤 저장하는 현재 명령 계약을 유지한다.

## Decision

- 수집 미완료 사유를 날짜별로 snapshot에 고정한다. 집계 대기, 보존 삭제, 사용량 수집 정책 중단, 대상 설치 없음, 설치 폐기, 손실 없는 수집 구간 부족을 구분한다. 구간 부족만으로 실제 사용량 손실을 단정하지 않는다.
- 개요 값의 reasons와 비교 reasons에 상세 사유를 추가한다. 비교 기간의 상세 사유에는 `previous_` 접두사를 붙인다. 현재·비교 기간의 불완전 사유 코드는 유지한다. 판정 결과가 같은 snapshot에서 바뀌지 않도록 query contract를 올린다.
- 시간상 미확정만 있으면 ‘집계 중’, 수집 근거 문제가 함께 있으면 ‘수집 불완전’을 표시한다. 식별 정보 등 다른 부분 집계와 값 확인 불가는 구분한다. CSV는 같은 사유를 보존한다.
- `/api/v1/organizations/{id}/contract-input-status`는 선택 기간 없이 현재 등록·미보관 벤더 중 계약이 없는 벤더 수와 목록, 필요한 필드 코드를 제공한다. 설정 조회 권한을 적용한다. snapshot·관측·좌석·청구 조회에 의존하지 않는다.
- 계약이 없는 경우 필수 입력은 플랜·좌석 수·월 좌석 단가다. 계약 만료·시작 예정·무료(0달러) 계약은 미입력으로 세지 않는다. 카탈로그 미등록 관측도 자동 계약 대상에 넣지 않는다.
- 공통 헤더의 ‘계약 입력 필요 N건’은 입력이 필요한 첫 벤더의 계약 편집창으로 바로 연결한다. 설정 상단에 별도 안내 섹션을 두지 않고 기존 벤더 행에서 누락 항목을 보여준다. 마지막 계약 저장 성공 후 조직 쿼리를 무효화해 안내를 숨긴다. 조회 실패를 완료 또는 0건으로 표시하지 않는다.
- 계약 입력은 사용 환산액·기간 완전성의 판정에 영향을 주지 않는다.

## Alternatives Considered

헤더에서 전체 설정 API를 읽으면 좌석·청구·관측 조회까지 모든 페이지에 따라온다. 수집 상태 API에 계약을 섞으면 독립적인 장애가 서로를 가리므로 별도 경량 조회를 사용한다.

## Consequences/Tradeoffs

### Positive

집계 대기와 수집 공백을 구별하고, 계약 입력으로 이어지는 공통 진입점이 생긴다.

### Negative

헤더 조회가 하나 늘고 snapshot 캐시에 날짜별 사유가 추가된다. 새 query contract 적용 시 기존 분석 snapshot 링크는 만료 처리된다.
