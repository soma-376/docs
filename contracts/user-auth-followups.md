# PROJ-107 사용자 인증 후속 티켓 초안

이 문서는 로컬 초안이다. Jira 이슈를 생성하거나 완료 처리하지 않았다.

## telemetryctl 사용자 로그인
- 연결: PROJ-107 서버 계약을 선행으로 둔다.
- 구현: login 명령, 브라우저 시작, 127.0.0.1/::1 동적 포트 callback, state 비교, S256 코드 교환, 사용자 세션 키링 항목.
- 설치 pit_/ptt_와 사용자 RT를 분리한다. 기존 credential 계정 이름을 덮어쓰지 않는다.
- AC: state/PKCE 실패, 코드 만료, 키링 실패, RT 갱신 직렬화, 재사용/응답 유실 시 재로그인.

## frontend 가입·로그인 화면
- 연결: PROJ-107 JSON API와 PROJ-109 인가.
- 구현: 초대 기반 최초 비밀번호 설정, tenant 식별과 로그인, CLI authorize 요청·callback 이동.
- 웹 토큰 저장 방식은 프런트 구현 ADR에서 정하며 현재 JSON 계약을 쿠키 구현으로 오해하지 않는다.
- AC: 가입/설치 어느 순서든 로그인 가능, 잠금·재시도 표시, 회원/관리자 대시보드 인가 분리.

## telemetryctl manifest 적용·복구
- 연결: PROJ-108 서버·스키마를 선행으로 둔다. 사용자 로그인 선행 티켓과도 연결한다.
- 구현: 사용자 RT 기반 GET, 캐시/자동 재시도 금지, RT 교환 직렬화, 새 manifest 적용·키링 저장 실패 처리.
- AC: 정책 적용 실패와 키링 실패, 응답 유실 후 재로그인, 구 설정에서 신호 수집/전송 동작을 명시한다.
- 서버는 적용 완료를 증명하지 않으므로 로컬 applied 상태를 서버 발급 성공과 동일시하지 않는다.

## ptt_ 유지 파급 확인
- PROJ-102의 검증기·해시·폐기와 telemetryctl 상위 전송 계약은 유지한다. AT 전환 구현 티켓은 만들지 않는다.
- PROJ-109: 사용자 API role·revision 검증 연결 및 정적 관리자 키 제거. OTLP 경로에 연결하지 않는다.
- infra: 사용자 API 활성화 시 secret 파일 마운트·공개키 선배포·Origin/IP 프록시 설정을 검증한다.

## 완료 게이트

이 파일은 미등록 초안이다. 실제 Jira 키는 등록 시 받으며 임의로 만들지 않는다.
계약 스키마 머지·상대 레포 리뷰와 연결 티켓 등록 전에는 PROJ-108 DoD를 완료로 표시하지 않는다.
