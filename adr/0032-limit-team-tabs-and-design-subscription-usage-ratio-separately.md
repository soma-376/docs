# 0032. 팀 탭은 비용과 토큰으로 제한하고 구독료 대비 사용 환산액은 별도로 설계한다.

## Status

Accepted — 세션 탭 정리는 구현 대상이며 비율 카드·계약 효력 이력은 후속 구현 설계다.

## Context

팀 분석의 화면 선택과 공유 세션 데이터는 범위가 다르다. 세션 탭을 제거하면서 공유 모델·정렬·CSV를 함께 지우면 개요와 상세·구성원 화면의 기존 기능이 사라진다. 세션 ID나 환산액이 없는 사용도 관측된 사용이므로 양수 세션·금액으로 행의 존재를 판정할 수 없다.

구독료 대비 사용 환산액에는 같은 제품·기간의 계약액이 필요하다. 현재 월 계약액과 수정 버전만으로 실제 요금 변경의 효력일과 입력 정정을 구분할 수 없다. 이 결정은 backend의 세션 계약·향후 계약 이력과 frontend의 선택 상태·표시·CSV에 걸친다.

## Decision

### 1. 세션 탭만 정리한다

팀 화면 선택 타입은 day/auto 모두 `cost | token`이다. 세션 탭과 그 선택에만 연결된 누적 추이·팀 비교·벤더 비중·툴팁·범례·증감·보조 표시를 제거한다. 개요의 세션 카드와 배치는 유지하며 새 비율 카드나 준비 중 카드를 넣지 않는다.

공유 모델·파서·원천·snapshot의 세션 식별자와 세션 집계·파생값·API는 유지한다. sessionCount·sessionsPerUser·tokensPerSession·equivalentCostPerSessionUsd·cumulativeSessionCount·sessionMixAvailable·sessionMixReason 및 API sort=session을 변경하지 않는다. PROJ-317의 서버 누적과 정확성 검증도 유지한다.

개요·팀 비용 표·상세·사용자·구성원 화면과 CSV의 세션 정보·상태·사유는 보존한다. chart_trend만 화면에서 선택한 비용·토큰 축을 따른다. 세션 ID 결손은 해당 지표만 제한하고 정상 비용·토큰 값을 숨기지 않는다.

팀 미배정 행은 정상 응답의 `pricedUsageRows + unpricedUsageRows > 0`으로 사용 관측을 판정한다. 필드 부재·조회 실패는 0이 아니며 행을 미사용으로 제거하는 근거로 삼지 않는다. 구성원은 기존 `periodUsage != null` 계약을 유지한다. 마지막 사용·활동·좌석 회수 판단은 변경하지 않는다.

탭 상태는 메모리 상태이므로 마이그레이션하지 않는다. 과거 axis=session·tab=session 링크는 비용 기본 화면을 보여주고 기간·비교·team 상세 선택을 보존한다. PROJ-317을 비활성화해도 비용·토큰 탭과 PROJ-316 호환 파서는 유지한다.

### 2. 비율 카드는 조건부 후속 설계로 채택한다

이름은 ‘구독료 대비 사용 환산액’이다. 조직 전체·선택 기간 v1으로 한정하며 팀·구성원·모델별 계약액 배분과 이전 기간 증감은 제공하지 않는다.

비율은 같은 제품·기간의 확인된 사용 환산액을 배분한 전체 구매 좌석 계약액으로 나누고 100을 곱한다. 100%를 넘을 수 있다. 미사용·미배정 좌석도 분모에 포함하며 이미 합산된 monthlySeatFeeUsd에 좌석 수를 다시 곱하지 않는다. 관측 도구 claude_code는 claude_team, codex는 openai_biz로 명시적으로 매핑한다.

같은 도구의 관측 사용은 구독 포함분과 별도 API 과금을 구분하지 않고 포함한다. 웹 등 미관측 사용은 포함하지 않는다. 관측 미지원 제품은 양쪽에서 제외하고 이유를 보인다. 지원 구매 제품은 사용 기록이 없어도 분모에 포함하며 대상 계약 누락은 조용히 제외하거나 0으로 채우지 않는다.

### 3. 계약 효력과 입력 정정을 구분한다

후속 계약 이력은 제품·좌석 수·좌석별 월 금액의 효력 시작·종료일, 실제 변경과 정정의 구분, 확인 근거와 적용 버전을 보존한다. recorded_at은 지식이 기록된 시각이며 계약 효력일이 아니다. 기존 버전만 보고 과거 효력 구간을 만들어 넣지 않는다. 현재 보관·만료 상태가 과거 유효 계약을 제거하지 않는다.

계약액은 KST 달력 월의 실제 일수로 일할 계산한다. 월 경계·효력 변경마다 구간을 분리한다. 진행 중 기간의 분자·분모는 같은 snapshot asOf까지이며 당일은 경과 시간 비율을 적용한다. 전체 미래는 계산하지 않는다. 중간 계산은 반올림하지 않고 최종 직렬화와 표시의 정밀도·반올림을 명세한다.

계약 구간 공백·중복·효력 불명, 대상 계약액 0, 전부 미환산, 조회 실패·관측 근거 없음이면 비율은 null이다. 일부 미환산은 확인된 부분합으로 비율을 제공하되 ‘확인된 금액 기준’과 미환산 건수를 표시한다. 정상 조회가 관측된 사용 없음을 입증하면 관측값 기준 0%와 ‘관측된 AI 사용 없음’을 표시하며 실제 비사용을 증명했다고 설명하지 않는다. 관측 근거와 보고 공백 해석은 PROJ-315 정책으로 인계한다.

### 4. 기존 API에 영향을 주지 않는 설계로 인계한다

후속 개요의 독립 영역 subscriptionUsageValue에 ratioPercent의 Value<number>, 확인된 사용 환산액·배분 계약액의 USD 문자열, 환산 행 수, effectivePeriod, allocationMethod=calendar_month_daily, 제품·계약 버전·효력 구간·월별 배분 근거와 제외 사유를 제공하는 안을 작성한다. frontend는 금액과 비율을 재계산하지 않는다.

비율은 소수 한 자리, 금액은 두 자리로 표시하고 상세에는 계산 정밀도를 제공한다. 100% 초과를 성공·절감으로 표현하는 색상이나 진행 막대를 쓰지 않는다. 실제 청구액·절감률·수익률·생산성 지표로 설명하지 않는다.

## Alternatives Considered

### A. 세션 필드와 집계를 함께 제거한다
- 장점: 공유 모델이 작아진다.
- 단점: 다른 화면·CSV·API의 기존 의미와 관측 여부 판정이 깨진다.
- 탈락 이유: 사용자 범위는 팀 탭 선택 제거다.

### B. 현재 월 계약액으로 즉시 비율 카드를 만든다
- 장점: 이력 입력 없이 계산할 수 있다.
- 단점: 월별 일수·과거 계약 변경·정정·진행일 시간 비율을 반영하지 못한다.
- 탈락 이유: 같은 제품·기간의 정확한 분모를 보장하지 못한다.

## Consequences/Tradeoffs

### Positive
- UI 정리와 세션 계약을 독립적으로 유지한다.
- 카드의 계산·불가 사유·근거가 명시되어 후속 구현이 임의 추정을 하지 않는다.

### Negative
- 화면에 선택하지 않는 세션 지표와 검증을 계속 유지한다.
- 계약 효력·정정 이력을 확보하기 전에는 비율 카드를 제공할 수 없다.

## Follow-up

- 계약 이력 보완·계산·상태 예제·API 안·텍스트 시안을 별도 명세로 인계한다. 이번 티켓에서 카드/API/이력 마이그레이션을 구현하지 않는다.

## Acceptance Criteria

- day/auto 비용·토큰 탭만 표시되며 기존 세션 화면·정렬·CSV·집계가 보존된다.
- 세션 ID와 환산액이 없는 사용도 미배정 행에서 유지되고 구성원 관측·마지막 사용이 변하지 않는다.
- 카드의 월중 변경·월 경계·윤년·진행일·계약 누락·0·미환산·무사용 사례를 검증 가능한 산식으로 남긴다.
