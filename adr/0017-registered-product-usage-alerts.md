# 0017. 조직에 등록한 제품을 기준으로 미등록 제품 사용을 알린다

## Status

Accepted — backend ADR 0051의 모델 허용·승인 도구 목록과 두 규칙을 대체한다. 비용 규칙, 평가 위치, 확인·이력 보존 결정은 그대로다.

## Context

영향을 받는 저장소는 pulsemetry-frontend와 pulsemetry-backend다. 관리자는 온보딩에서 계약 벤더의 제품을 등록한다.
별도 모델 허용 목록과 승인 도구 목록은 이 등록과 중복되고, 모델 공급자만으로 계약 제품을 판단하면 다른 공급자의 모델을 제공하는 제품을 잘못 분류한다.
사용자가 선택한 기준은 등록 제품이며, 모델 카탈로그나 MCP 승인 목록을 새로 관리하지 않는다.

## Decision

1. 온보딩은 수집 정책 → 계약 벤더 등록 → 팀·구성원 순서를 유지한다. 벤더의 제품을 카탈로그에서 선택하고 플랜·좌석 수·단가는 나중에 입력할 수 있다.
   등록은 해당 제품을 조직의 사용 기준에 넣는다. 계약 만료·미입력과 제품 삭제는 구분하며, 계약액이나 유효기간으로 등록 여부를 추정하지 않는다.
2. 조직의 기준은 보관되지 않은 managed_vendors.kind다. 별도 허용 벤더·모델·도구 표를 만들지 않는다.
3. 새 규칙 product_not_registered는 security, 1 events, rolling_24_hours다. 등록 제품이 하나 이상일 때 켤 수 있다.
   비어 있으면 registered_products_not_configured이며, 켜진 뒤 마지막 제품을 삭제한 경우에도 평가는 같은 사유로 not_evaluated다.
4. 관측은 active·mapped 로그의 model.response.usage·primary 행을 사용한다. product를 vendor_catalog_observed_products의 명시 매핑으로 카탈로그 제품에 연결한다.
   매핑된 제품이 조직에 등록되어 있지 않으면 제품별로 24시간 묶음을 만든다. 모델 이름·공급자·본문·tool_name으로 제품을 추정하지 않는다.
   매핑되지 않은 제품과 unknown은 판정 대상에서 제외하고 기존 관측 화면의 미분류 상태로 둔다.
5. 알림은 제품 ID·제품명·관측 건수·구성원·시각을 보여 준다. 개인 결제·계약 위반·차단을 의미하지 않는다.
   규칙을 켠 관리자는 수집된 사용에 대한 알림을 받는다. 관측되지 않은 도구를 찾는 기능은 포함하지 않는다.
6. 규칙의 가용성과 켜짐은 서버가 정한다. 설정 화면은 모델·도구 목록 편집과 기존 두 토글을 제거하고 미등록 제품 사용 토글을 제공한다.
   운영/보안 페이지 구성은 변경하지 않고 공통 알림 표시기가 새 규칙을 읽도록 한다.
7. Flyway는 alert_rule_definitions에 active를 추가하고 기존 두 규칙을 비활성화하며 저장된 켜짐을 끈다.
   새 규칙은 자동으로 켜지지 않는다. 이전 목록 표와 알림·확인 이력은 보존하며 목록 편집 API와 설정 응답의 alertLists는 제거한다.
   dashboard-cache 마이그레이션은 이전 규칙의 열린 묶음만 닫는다. 과거 알림은 원래 규칙명으로 계속 조회·확인할 수 있다.
8. 등록 변경 이후의 평가는 당시 등록 목록으로 진행한다. 과거 알림을 새 규칙으로 바꾸거나 소급 삭제하지 않는다.

## Alternatives Considered

- 공급자 단위 비교: 제품이 여러 공급자의 모델을 제공할 수 있어 채택하지 않는다.
- 모델·MCP 승인 카탈로그: 관리 범위와 사용자 입력을 늘리므로 채택하지 않는다.
- 이전 규칙을 새 규칙으로 자동 전환: 판정 의미가 달라 채택하지 않는다.

## Consequences/Tradeoffs

### Positive

온보딩의 제품 등록 하나가 비교 기준이 된다. 알림에서 어떤 제품의 사용이 관측됐는지 설명할 수 있다.

### Negative

수집 프로파일과 명시 매핑이 없는 제품은 판정하지 못한다. 등록된 제품 안의 모델별 제한은 제공하지 않는다.
청구 계정이나 결제 수단은 관측 근거가 아니므로 개인 구독인지 판별하지 못한다.
