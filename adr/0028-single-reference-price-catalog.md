# 0028. 서버는 단일 참조 단가표를 사용하고 저장된 환산액을 합산한다

## Status

Accepted — ADR 0008의 가격판 선택·버전 기록과 ADR 0011의 같은 가격판 합산 조건을 대체한다. 참조 평가의 출처·토큰 의미·null·부분합·원천 보존 규칙은 유지한다.

## Context

ADR 0008은 재현과 재평가 대상 추적을 위해 불변 가격 프로파일과 `pricing_version`을 채택했다. ADR 0011은 다른 가격판의 금액이 섞이면 부분합도 null로 정했다.

이 조건은 이미 계산된 사용량을 가린다. 비교 기간이나 다른 구성원의 사용량에 다른 가격판이 있으면 선택한 구성원의 계산 가능한 금액까지 확인 불가가 될 수 있다. 제품에는 가격판 선택이나 가격판별 비교가 필요하지 않다.

이 결정은 `pulsemetry-backend`의 계산·저장·조회, `pulsemetry-frontend`의 응답 해석·표시, `infra`의 서버 실행 설정에 걸린다.

## Decision

1. 서버는 저장소에 포함된 단일 참조 단가표로 새 사용량을 계산한다. 실행 설정·요청·운영 도구에서 가격 프로파일이나 버전을 선택하지 않는다. 단가표 변경은 코드 리뷰와 배포로 적용한다.
2. 가격판 식별자를 관측·분석 해시·대시보드 snapshot·응답에 새로 기록하지 않는다. 가격판 목록과 `pricingVersion`, `pricing_version_mixed` 같은 응답·표시 조건을 제거한다. 이 결정은 가격판에만 적용하며 정규화 규칙의 변경 번호와 행 교체 순서는 유지한다.
   - 배포 중 구버전 앱과의 호환 및 복구를 위해 기존 nullable `pricing_version`과 기본값이 빈 목록인 `pricing_versions` 물리 컬럼은 남길 수 있다. 기존 값은 보존하되 새 관측과 snapshot은 가격판 식별자를 쓰거나 복사하지 않으며, 조회·계산에도 사용하지 않는다. 컬럼을 삭제하는 파괴적 정리는 별도 작업이다.
3. 단가의 출처·평가 조건·명시적 별칭은 단일 카탈로그의 문서와 코드에서 관리한다. 공급자 공식 문서로 확인한 단가를 우선하고 나머지는 기존 Codeburn 0.9.24 참조 자료를 사용한다. 원본 자료의 버전·해시는 출처 증거이며 선택 가능한 가격판이나 관측의 가격판 식별자가 아니다.
4. 사용 환산액은 각 관측에 저장된 USD 참조 평가 금액의 합이다. 가격표의 과거 차이만으로 전체값·부분합·평균·비중·비교를 막지 않는다. 비교 기간이나 다른 그룹의 가격표 차이도 현재 범위의 값을 가리지 않는다.
5. 기존에 저장된 금액과 관측 ID·시각·토큰·모델·소속·원본 참조는 보존한다. 가격표 변경이나 이 전환으로 과거 행을 자동 재계산하지 않는다. 따라서 합계가 모든 과거 사용량을 현재 단가로 다시 평가한 값이라는 뜻은 아니다.
6. 미등록 모델·미검증 토큰 의미·필수 성분 누락은 계속 null이다. 미가격 행이 하나라도 있는 범위의 전체 환산액은 null이며, 계산된 행의 부분합은 별도로 제공한다. 계산된 행이 없으면 부분합도 null이고, 완전하게 관측된 빈 범위만 0이다. 실제 0원 관측은 보존한다.
7. Standard/global/USD, 비중복 토큰 성분, Claude 캐시 생성의 5분 참조 단가, 요청 길이별 구간 선택은 ADR 0008을 따른다. 실제 청구액·구독 금액·조직 계약액·벤더 보고 금액과 구분한다. 화면·CSV에서도 전체값과 부분합, 관측 공백을 구분한다.
8. 저장 사용량의 명시적 재평가는 현재 단일 카탈로그를 쓴다. 범위·실행 입력을 고정하고 원천 보존·재실행 안전성·새 snapshot 반영을 유지한다. 가격판 변경만으로 재평가 대상을 고르거나 자동 실행하지 않는다.

이 결정의 범위는 서버의 사용 환산 경로다. telemetryctl의 독립적인 로컬 사용량 가격표와 CLI 릴리스 버전은 변경하지 않는다.

## Alternatives Considered

### A. 가격판 혼재 차단만 제거한다

- 장점: 응답 금액을 빠르게 복구하며 과거 가격판 추적을 유지한다.
- 단점: 사용하지 않는 가격판 선택·기록·설정이 남는다.
- 탈락 이유: 단일 가격표 운영이라는 제품 결정에 맞지 않는다.

### B. 모든 과거 사용량을 현재 단가로 즉시 재계산한다

- 장점: 같은 가격 기준의 합계를 만든다.
- 단점: 기존 금액을 바꾸며 원천·의미가 부족한 행의 복구를 보장하지 못한다.
- 탈락 이유: 버저닝 제거에 불필요한 데이터 변경이다. 재평가는 별도 운영 작업으로 남긴다.

## Consequences/Tradeoffs

### Positive

- 계산 가능한 금액이 다른 가격판이나 비교 기간 때문에 사라지지 않는다.
- 가격판 선택 설정과 관측별 버전 관리가 없어져 운영 경로가 단순해진다.
- 기존 금액과 원천 사용량을 보존한다.

### Negative

- 과거 행의 단가를 가격판 필드 하나로 재현할 수 없다. 당시 코드·배포 이력과 원천 사용량이 필요하다.
- 가격 변경 전후의 금액이 한 합계에 들어갈 수 있다. 합계는 저장된 평가액이며 현재 단가로 통일한 재평가액으로 설명하지 않는다.
- 가격표 출처를 보관하고 갱신 내용을 검토할 운영 책임은 계속 필요하다.

## Acceptance Criteria

- 실행 경로의 가격판 선택 설정과 새 버전 기록, 대시보드 가격판 필드·혼재 사유가 제거된다.
- 기존 서로 다른 가격판으로 계산된 행과 신규 행의 합계가 저장된 USD 금액의 합과 같다. 비교 기간·그룹의 다른 가격판이 합계를 가리지 않는다.
- 미가격·전부 미가격·실제 0·관측이 완전한 빈 기간·불완전 기간의 전체값과 부분합 규칙이 유지된다.
- 기존 금액·관측 키·원천 토큰은 전환으로 바뀌지 않으며, 재평가는 명시한 범위에서만 실행된다.
- dev의 실제 수집 사용량을 API와 브라우저에서 확인하고 배포 버전을 기록한다.
