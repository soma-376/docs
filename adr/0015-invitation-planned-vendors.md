# 0015. 초대 시 선택한 사용 예정 제품은 실제 좌석과 분리한다

## Status
Accepted — 사용자 요청에 따른 구현. 양쪽 저장소의 병합·배포는 별도다.

## Context
프론트의 구성원 초대와 온보딩에서 팀·역할과 함께 사용할 제품을 지정한다. 백엔드는 초대 시 구성원을 만들지만 제품 선택은 실제 벤더 계정 발급이나 좌석 배정의 증거가 아니다.

## Decision
- 조직에 등록된 활성 제품을 선택 사항으로 복수 지정한다. 필드는 `plannedVendorIds`다.
- `enrollment.members.planned_vendor_ids`에 저장하고 초대 목록·구성원 조회에 반환한다. 빈 배열은 미지정이다.
- 일괄 초대의 기본 선택을 개인별로 덮어쓸 수 있다. 온보딩과 일반 초대는 같은 폼을 사용한다.
- 같은 조직의 등록 제품만 허용한다. 누락 필드는 기존 초대와 호환되며 신규 초대에서 빈 배열이다.
- 기존 구성원·이미 초대된 사람의 선택은 중복 초대로 덮어쓰지 않는다. 구성원 PATCH에서 expectedVersion으로 편집한다.
- 좌석 원장·청구·수집 권한·SSO 인가는 변경하지 않는다. 실제 배정은 기존 벤더 동기화·관리자 확인 흐름을 따른다.
- 제품 보관 후에도 저장된 선택은 보존하고 화면에서 등록 해제된 제품으로 표시한다. 신규 선택에는 허용하지 않는다.

## Alternatives Considered
- 초대와 동시에 실제 좌석 생성: 벤더 배정 사실 없이 집계를 늘리므로 채택하지 않는다.
- 프론트 초안만 저장: 새로고침·다른 관리자 간 공유가 불가능하므로 채택하지 않는다.

## Consequences/Tradeoffs
### Positive
초대 단계에서 제품 사용 계획을 남기면서 좌석 지표의 의미를 유지한다.
### Negative
사용 예정 목록과 실제 좌석이 다를 수 있다. 선택만으로 벤더 계정을 생성하지 않으며 별도 배정 작업이 필요하다.
