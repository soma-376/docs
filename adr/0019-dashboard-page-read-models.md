# 0019. 대시보드 조회 응답은 각 화면의 값과 상태에 맞춘다

## Status

Accepted — backend ADR 0044의 설정 응답에 감지 제품·미분류 관측을 포함하는 결정과 ADR 0045의 페이지별 제품 사용 응답 범위를 현재 화면의 투영으로 부분 대체한다. 제품 매핑·snapshot 고정·기간 완전성·인가·관리 명령은 유지한다.

## Context

pulsemetry-backend와 pulsemetry-frontend의 팀 분석·구성원·운영·설정 화면이 범용 분석 응답에서 사용하지 않는 필드를 버리고 값을 다시 계산한다. 개요는 ADR 0017·0018에 따라 화면별 값과 상태를 이미 사용한다. 같은 값의 확인 불가 사유가 다른 화면에서 사라지지 않아야 한다.

## Decision

- 팀 분석·구성원·운영·설정의 조회 응답은 화면의 표·카드·상세 편집·페이지네이션에 필요한 필드만 반환한다. 헤더 수집 상태와 별도 카탈로그 조회를 페이지 응답에 중복하지 않는다.
- 분석 값은 `value/status/reasons`로 확인된 0, 부분 관측, 값 확인 불가를 구분한다. 비용·토큰·세션 증감과 의미가 있는 파생 지표는 서버가 판단한다. 프론트는 표시·정렬·차트 좌표만 가공한다. 기간 불완전과 식별·단가·토큰 결손의 기존 판정 조건을 완화하지 않는다.
- 팀 목록·직접 연결 상세·구성원 페이지네이션은 같은 snapshot을 유지한다. 팀 관리 명단과 사용 당시 대표 팀 귀속은 구분한다.
- 구성원의 현재 명단·좌석과 최근 사용량을 분리한다. 사용량이 없는 기간에도 현재 명단과 관리 동작은 유지한다. 화면에 없는 제품 분해·토큰 세부를 조회하지 않는다.
- 운영·보안은 기존 알림 목록 API와 페이지네이션을 유지한다. 평가 상태와 사유는 보존하고 내부 규칙 평가 기록·화면에 없는 evidence는 응답에서 제외한다. 알림 확인 명령의 의미는 바꾸지 않는다.
- 설정 첫 응답에는 요약 카드·벤더 행·수집 정책·정책 적용 현황·알림 규칙을 둔다. 계약 편집·좌석·커넥터에 필요한 상세는 벤더 상세 조회에서 받는다. 감지 제품·미분류 관측은 설정 화면에 표시하지 않으므로 첫 응답에 포함하지 않는다. 계약 입력 안내는 공통 헤더와 기존 벤더 행에만 둔다.
- 현재 조회 단위와 로딩·재시도 경계를 유지한다. 화면마다 무조건 단일 API로 합치지 않는다. 조회 실패를 값 없음·0건으로 바꾸거나 다른 snapshot의 값으로 채우지 않는다.
- CSV는 해당 화면에 표시하는 값과 상태·사유를 내보낸다. 화면에 없는 내부 평가 기록이나 계약 상세를 추가하지 않는다.

## Alternatives Considered

범용 응답을 유지하면 불필요한 쿼리와 필드, 프론트 계산이 계속된다. 모든 페이지를 단일 API로 합치면 현재 명단·분석 기간·상세 편집·페이지네이션의 갱신 경계가 섞이므로 채택하지 않는다.

## Consequences/Tradeoffs

### Positive

화면과 CSV가 서버가 판단한 동일한 값·상태를 사용한다. 사용하지 않는 집계와 중복 메타데이터를 제거하고 상세 조회의 목적이 분명해진다.

### Negative

응답 변경은 프론트와 백엔드의 동시 반영이 필요하다. 화면이 바뀌면 API 투영과 계약 테스트도 함께 수정해야 한다.
